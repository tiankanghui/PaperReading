# 问题与关键点

## 一道电脑操作题，为什么不只是一句要求？

“给客户发邮件并附上交易记录”只说明要做什么。Agent 还需要实际存在的客户名单、邮件模板、交易表和可操作的邮箱界面；做完后，还需要检查收件人、内容和附件的程序。CUA-Gym 把这三样一起准备，构成一道可以反复练习并自动判分的题。

操作记录是之后让 Agent 真正做题才产生的，包括它看到的截图和执行的点击、输入等动作。题目与操作记录因此是不同的训练材料。依据：第 1、2.1 节，PDF 第 1–3 页；附录 A.6，PDF 第 20–21 页。

## 任务要求、材料清单和电脑状态有什么区别？

任务要求说“要完成什么”，例如给名单中的客户发邮件。材料清单说“开始前应准备什么”，例如客户名单、模板和交易表。图中的 Task 与 Context 分别对应这两部分。

电脑状态说的是“某一时刻实际有什么”：名单是否已经放好、邮箱中有哪些邮件、页面是否打开。开始时，新邮件尚未发出；正确完成后，新邮件及附件已经对应好。两种状态之间应只改变任务要求完成的内容。依据：Figure 1、第 2.1 节与附录 G.3，PDF 第 3、77–78 页。

## 为什么需要两台电脑？

一台准备“还没做任务”的情况，另一台准备“正确完成后”的情况。用同一个判分程序检查它们，前者应该得 0，后者应该得 1，才能说明程序在这两种情况下判断正确。

第二台电脑里的正确结果可以直接用代码建立，所以它主要用于测试判分，并没有给被训练的 Agent 演示点击步骤。之后还要让 Agent 从第一台电脑开始，通过界面真正操作，检查任务是否做得到。依据：第 2.1 节与附录 A.3/A.4，PDF 第 3–4、16–18 页。

## 功能树与场景矩阵分别帮助出什么题？

功能树是软件功能的分层清单，例如“格式 → 单元格外观 → 条件格式”，帮助出题者知道要练哪些具体操作。场景矩阵按平台、领域、难度、使用场景和是否需要多个应用分类统计，帮助发现哪类题太少。

论文先尽量铺开不同功能，再根据统计补缺，最后补充此前失败分析中发现的特殊操作与软件组合。少见类型更容易被抽到，避免题目集中在几个常用功能。文字去重只能减少相似问句；是否学到新操作，还要看实际任务有没有变化。依据：附录 A.2，PDF 第 14–16 页。

## 写判分的 Agent 能看什么，为什么要隔开生成脚本？

准备两台电脑的 Agent 叫 Generator；写判分的 Agent 叫 Discriminator。后者能读任务说明、材料清单和应用说明，也能查看两台电脑的实际结果，但看不到 Generator 的准备脚本和工作目录。

隔开脚本，是为了减少“照着生成过程写检查”的捷径。例如只认生成时的文件名，而不检查文件内容。正确完成后的结果仍然可见；这种安排也不能保证所有宽松或错误的检查都会被发现。依据：第 2.1 节、附录 Table 1 与 G.4，PDF 第 3、17、79 页。

## 开始得 0、完成得 1，为什么还不能说明判分完全可靠？

这只检查了两个例子。程序可能正确拒绝尚未发邮件的情况、接受正确邮件，却也接受“收件人错误但附件名正确”的结果。因此还需要检查代码、审查任务，并让 Agent 实际尝试。

更强的检查可以故意准备错误收件人、漏附件、错值或破坏输入等情况，看程序是否拒绝。这是根据现有检查范围提出的建议，论文没有报告系统的反例测试。依据：附录 A.3 与第 6 节，PDF 第 16–17、10 页。

## 发现分数不对时，应该修材料、正确结果还是判分程序？

先对照任务要求检查实际内容。附录的表格例子中，两个场景的名称正确，但其中一个存入了错误的单元格值，应该修准备正确结果的脚本。另一个可能的错误是判分程序把初始就存在的模板邮件算作任务成果，这时应该修判分。

两个准备脚本能运行完，不代表结果正确；正确结果得不到满分，也不能单凭这一点认定判分程序正确。每次失败报告都应指出具体哪项检查没过，才能安排有针对性的修改。依据：附录 A.3、E.4、G.3/G.5，PDF 第 16–17、69–70、78、80 页。

## 为什么已有材料不能单独给分？

任务的分数应该来自这次要求完成的新结果。邮件模板原本就在“已发送”文件夹中，所以“该文件夹里有邮件”不能说明 Agent 完成了新的发送任务。

原文的工作表例子也一样：要求隐藏 Raw Data，而 Summary 原本就可见。“Summary 可见”不能单独给分；可以检查“Raw Data 已隐藏且 Summary 仍可见”。文件完整性可以作为必须满足的条件，但不应该让什么都没做的 Agent 得分。依据：附录 G.4，PDF 第 79 页。

## 实际操作与截图检查各补查什么？

一次完整的操作尝试叫 rollout。让较强的 Agent 实际尝试，可以检查所需材料是否可见、界面是否支持操作，以及能否在规定步数内完成。

操作结束后，程序检查文件和应用数据；另一个能看图的模型检查最终截图。例如数据值正确但图表缺坐标轴标签，截图可能发现程序遗漏。两种判断明显不同，就反馈修改判分并重试。Agent 失败仍不证明任务绝对无解，两个判断一致也可能一起漏掉问题。依据：附录 A.4，PDF 第 17–18 页。

## 一个训练网站怎样承载许多题，又避免互相干扰？

模仿真实网站的训练网站称为 mock。给同一个邮箱网站装入不同客户和邮件，就能形成不同练习，称为状态注入。保存开始时与现在的数据，再列出变化，称为 diff；判分仍需检查具体内容，不能只看“邮件列表变了”。

每次练习用独立编号 sid，读写数据、上传附件、重置和判分都对应这个编号，避免不同 Agent 的操作混在一起。这样的训练网站容易重置，但仍简化了真实登录、网络和第三方服务行为。依据：Figure 3、附录 B.3 与第 6 节，PDF 第 5、25–26、10 页。

## 环境越多是否已经被证明能改善强化学习？

论文有两组不同实验。固定最初的示范学习结果后，用 1.4K、3K、12K 道题进行强化学习，支持题目数量增加有收益。

软件环境数量的对照则使用成功操作示范进行监督微调：固定 3K 条示范，10→80 个环境将评测成绩从 57.8% 提高到 58.8%；固定 80 个环境，3K→6K 条示范再提高到 60.7%。因此，环境数量的直接对照是在学习示范的设置下进行的，不能称为强化学习中的环境数量对照；首尾 2.9 个百分点也同时包含环境和示范数量的变化。依据：第 4.1、4.2 节与 Figures 7、8，PDF 第 7–9 页。
